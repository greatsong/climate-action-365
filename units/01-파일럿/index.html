Unit 1. 파일럿 한 대 세팅

이번 시간에는 우리 교실에서 측정될 환경 데이터를 만들어 줄 첫 번째 노드 한 대를 직접 세팅해 보겠습니다. 16개 교실에 똑같은 박스를 풀어놓기 전에, 먼저 한 대로 ‘이 코드가 실제 보드 위에서 정말 동작하는지’를 손으로 확인해야 합니다. 16배의 시간을 16분의 1로 줄이는 가장 확실한 방법은 ‘한 번 제대로 만든 한 대’입니다.

이번 단원의 학습 흐름은 단순합니다. 라즈베리 파이 피코 2 WH에 마이크로파이썬(MicroPython) 펌웨어를 설치하고, 그 위에 우리가 미리 만들어 둔 세 개의 파이썬 파일을 올린 다음, 온습도 센서(SHT40)와 조도 센서(BH1750)를 각각 알맞은 자리에 꽂아 보드를 부팅합니다. 모든 단계의 결과는 셸(Shell) 창에 한 줄씩 출력되므로, 무엇이 어디에서 어떻게 멈췄는지 즉시 알 수 있습니다.

여기서 한 가지 중요한 점을 미리 짚어 두겠습니다. 우리는 이번 단원에서 ‘코드를 새로 짜는 일’을 거의 하지 않습니다. 펌웨어 파일도 미리 만들어 두었고, 회로 배선도 표준이 정해져 있습니다. 그렇다면 이번 단원의 진짜 학습 포인트는 무엇일까요? 바로 ‘무엇이 잘못되었을 때, 어디를 봐야 하는지를 익히는 일’입니다. 한 대를 만들면서 보드의 LED, Thonny의 셸 메시지, 서버의 로그, 그리고 대시보드의 카드 — 이 네 가지 신호가 어떻게 묶여 있는지를 손으로 체험합니다.

이번 시간의 미션

작업이 끝났을 때 다음 네 가지가 모두 사실이어야 합니다.

  1. 피코 본체의 LED가 켜져 있고, Thonny 셸에 30초마다 측정 로그 한 줄이 찍힌다.
  2. 셸의 I2C 스캔 줄에 0x44와 0x23이 함께 보인다.
  3. 셸 출력에 WiFi 연결됨: IP=…이 한 번 이상 나타난다.
  4. 컴퓨터 브라우저로 서버의 /nodes 주소를 열면 방금 만든 노드가 목록에 보인다.

이 네 가지를 모두 통과시키는 것이 이번 단원의 목표입니다.

🧠 컴퓨팅 사고력 · 네 가지 신호의 인과 사슬

  1. LED가 꺼져 있다면 전원 단계, 셸이 비어 있다면 펌웨어 단계, I2C 스캔에 빈자리가 있다면 배선 단계, 대시보드에 카드가 없다면 네트워크 단계의 문제입니다.
  2. 네 가지 신호는 ‘앞 단계가 통과해야 다음 신호가 켜지는’ 인과 사슬을 이룹니다.
  3. 장애가 났을 때 ‘어디까지 켜져 있는지’를 빠르게 훑으면, 디버깅 시간이 절반으로 줄어듭니다.

📷 그림 1-1 · 완성된 파일럿 노드 한 대 전체 모습 촬영 메모 — Pico 2 WH + Grove Shield + SHT40 + BH1750 + 마이크로 USB 케이블이 한 컷에 들어오게. 책상 위 자연광, 위에서 약 30도 각도.

단계 1 — 마이크로파이썬 펌웨어 설치

피코 보드 안에는 처음에는 아무 프로그램도 없습니다. 우리는 그 위에 ‘파이썬 코드를 받아 실행해 주는 인터프리터’인 마이크로파이썬(MicroPython)을 먼저 설치합니다. 이 작업은 한 번만 하면 되고, 한 번 설치된 펌웨어는 전원이 꺼져도 사라지지 않습니다.

이 단계의 핵심은 ‘보드를 USB 메모리처럼 인식시켜, 펌웨어 파일을 그 위에 드래그&드롭한다’는 점에 있습니다. 별도의 설치 프로그램이나 명령어가 필요 없는, 가장 단순한 펌웨어 설치 방식입니다. 다만 한 가지 조건이 있습니다. 보드를 ‘부트로더(bootloader)’ 상태로 진입시켜야 한다는 점입니다.

1.1 펌웨어 파일 내려받기

웹브라우저로 다음 주소에 접속해 가장 최신의 .uf2 파일을 내려받습니다.

예를 들어 RPI_PICO2_W-20251225-v1.24.0.uf2 같은 이름의 파일이 컴퓨터의 ‘다운로드’ 폴더에 저장됩니다. 파일 이름에 PICO2_W가 들어 있어야 합니다. PICO_W(1세대)와 PICO2_W(2세대)는 칩이 달라 펌웨어가 호환되지 않으니 이름을 꼭 확인합니다.

1.2 부트로더 모드로 진입

피코 보드의 BOOTSEL 글자가 인쇄된 작은 흰색 버튼을 누른 채로 마이크로 USB를 컴퓨터에 꽂습니다. 이때 버튼을 누른 상태로 USB를 끼우는 ‘동시 동작’이 중요합니다. 보드가 USB 메모리(예: RPI-RP2 또는 RP2350)로 컴퓨터에 마운트되면 그제서야 버튼에서 손을 뗍니다.

📷 그림 1-2 · BOOTSEL 버튼을 누른 채로 USB를 꽂는 모습 촬영 메모 — 손가락이 BOOTSEL 버튼 위에 있고, 반대쪽 손이 USB 커넥터를 보드에 꽂는 순간. 보드 윗면이 잘 보이게.

1.3 펌웨어 드래그&드롭

컴퓨터의 파일 탐색기에서 다운로드한 .uf2 파일을 방금 마운트된 RPI-RP2 드라이브 위로 끌어다 놓습니다. 복사가 끝나면 보드가 자동으로 재부팅되고, 드라이브가 사라집니다. 이 시점에 펌웨어 설치가 완료된 것입니다.

Tip 펌웨어가 정말 설치되었는지 확인

  1. 보드 본체의 작은 초록 LED가 켜져 있으면 정상 동작 신호입니다.
  2. Thonny를 연결하면 셸에 MicroPython v1.24.0 … 같은 한 줄이 보입니다.
  3. 다시 BOOTSEL 모드로 들어가지 않습니다. 보통 USB만 꽂아도 정상 부팅됩니다.

단계 2 — Thonny 설치와 보드 연결

Thonny는 마이크로파이썬 보드와 가장 친한 무료 코드 편집기입니다. 우리는 이 도구로 보드에 코드를 올리고, 셸 창에서 보드의 출력을 읽습니다.

2.1 Thonny 내려받기

Windows·macOS·Linux 모두에서 같은 화면을 제공합니다. 설치 후 처음 실행하면 빈 편집기가 열립니다.

2.2 인터프리터 설정

상단 메뉴에서 Tools → Options → Interpreter를 차례로 엽니다.

항목값
InterpreterMicroPython (Raspberry Pi Pico)
Port자동 인식 또는 수동 선택

포트가 자동으로 잡히지 않을 때는 보드를 한 번 빼고 다시 꽂아 봅니다. 그래도 안 되면 다음 이름들을 후보로 둡니다.

  • Windows: COM3, COM5 같은 이름
  • macOS: /dev/cu.usbmodem… 으로 시작하는 이름
  • Linux: /dev/ttyACM0

OK를 누른 뒤 화면 우측 아래의 빨간 정지(⏹) 버튼을 한 번 클릭합니다. 보드가 재시작되면서 셸 창에 다음과 같은 안내가 나타납니다.

>>> 프롬프트가 보이면 연결 성공입니다.

📷 그림 1-3 · Thonny의 인터프리터 설정 화면 촬영 메모 — Tools > Options > Interpreter 탭이 열려 있고, MicroPython (Raspberry Pi Pico)과 포트가 선택된 모습. 우측 하단 OK 버튼이 살짝 보이게.

2.3 셸에서 한 줄 시험

연결을 확인하는 가장 빠른 방법은 셸에 직접 한 줄을 입력해 보는 것입니다.

hello, pico가 그대로 돌아오면 보드가 우리의 명령을 받고 응답하고 있다는 뜻입니다.

🔬 가설을 세워 봅시다 · 보드의 LED는 무엇을 알려 주는가

  1. 보드 위의 작은 초록 LED는 평소에 꺼져 있을까요, 켜져 있을까요?
  2. from machine import Pin; Pin("LED", Pin.OUT).on()을 셸에 입력해 보면 어떻게 될지 예측해 봅니다.
  3. 실제로 입력한 뒤 결과와 예측을 비교합니다. 같다면 우리는 이 보드의 LED가 ‘Pin("LED")에 대응한다’는 가설을 검증한 셈입니다.

단계 3 — 센서 배선

Grove Shield는 피코 위에 그대로 끼우는 확장 보드로, 4핀 Grove 커넥터를 여러 개 제공합니다. 우리는 그중 ‘I2C’라고 인쇄된 슬롯 두 개에 센서를 꽂습니다. 두 슬롯은 모두 같은 I2C 버스(GP4·GP5)로 묶여 있어, 어느 쪽에 꽂아도 동일하게 동작합니다.

3.1 SHT40 연결

SHT40 Grove 모듈은 양쪽 끝이 모두 Grove 커넥터입니다. 그러므로 다음과 같이 연결합니다.

Grove 커넥터는 한 방향으로만 끼워지도록 설계되어 있어, 거꾸로 꽂아 손상되는 일은 없습니다. 약간 빡빡하게 들어가지만 무리해서 휘게 만들지는 않습니다.

3.2 BH1750 GY-302 연결

BH1750을 단 GY-302 모듈은 일반 점퍼 핀 4개로 되어 있어 한쪽 끝을 변환 케이블로 받아 줍니다. 색상 매핑은 다음과 같습니다(케이블 제조사마다 색이 달라질 수 있으니 첫 한 대를 만들 때 반드시 실측합니다).

GY-302 핀변환 케이블 점퍼 색 (표준)Grove 신호
VCC빨강3.3V
GND검정GND
SCL노랑I2C 클럭
SDA흰색I2C 데이터

Tip VCC와 GND가 바뀌면 모듈이 즉시 손상됩니다

  1. 전원을 켜기 전, ‘빨강이 VCC, 검정이 GND’인지를 두 눈으로 확인합니다.
  2. 멀티미터가 있다면 Grove 커넥터의 1번 핀이 GND, 2번 핀이 VCC임을 한 번 더 짚어 봅니다.
  3. SDA·SCL이 바뀌어도 모듈은 손상되지 않지만 I2C 스캔에서 주소가 잡히지 않습니다.

3.3 같은 I2C 버스에 두 모듈이 함께 사는 방법

두 모듈은 모두 GP4(SDA)·GP5(SCL) 한 쌍의 선에 병렬로 매달려 있습니다. 그런데 어떻게 충돌하지 않고 따로따로 응답할 수 있을까요? 정답은 **주소(address)**입니다. SHT40은 0x44로 자신을 호명할 때만 응답하고, BH1750은 0x23으로 호명할 때만 응답합니다. 한 줄의 전화선에 여러 명이 매달려 있어도, ‘이름을 부른 사람만 대답한다’는 약속이 있으면 서로 헷갈리지 않는 것과 같습니다.

📷 그림 1-4 · SHT40과 BH1750을 모두 꽂은 Grove Shield 윗면 촬영 메모 — Grove Shield 위의 두 I2C 슬롯에 케이블이 각각 꽂혀 있고, 반대쪽 두 센서가 책상에 살짝 펼쳐진 모습. 색상 매핑이 잘 보이게 위에서 촬영.

코드 1-3

핵심 한 줄 풀이

이 코드의 가장 영리한 부분은 buffer.jsonl 파일을 통한 오프라인 버퍼링입니다. 서버나 WiFi가 잠시 죽어도, 측정값은 일단 Pico의 flash에 한 줄씩 차곡차곡 쌓입니다. 다음 번 전송이 성공하면 그 동안 쌓인 줄을 함께 보내고, 파일을 비웁니다. 학교 망이 점검 등으로 30분 끊기더라도 그 시간 동안의 데이터가 모두 살아남는 이유가 여기에 있습니다. 최대 200건(약 100분치)까지 보관하므로 그보다 긴 단절은 가장 오래된 데이터부터 잘려 나갑니다.

또 하나 짚어 둘 부분은 WDT(timeout=8000) 한 줄입니다. ‘8초 안에 코드가 한 번이라도 wdt.feed()를 호출하지 않으면 보드를 강제로 재시작한다’는 약속을 마이크로파이썬에게 거는 명령입니다. 코드가 어떤 이유로든 무한 루프에 빠지면, 8초 뒤 보드가 스스로 살아나도록 합니다. 사람이 16개 교실을 매일 들여다보지 않아도 시스템이 스스로를 추스르도록 만드는 가장 작은 장치입니다.

🧠 컴퓨팅 사고력 · 버퍼링과 와치독, 두 가지 ‘자기 치유’

  1. 오프라인 버퍼링(buffer.jsonl)은 ‘외부 환경(서버·WiFi)이 잠시 죽어도 데이터는 안 잃는다’는 약속입니다.
  2. 와치독 타이머(WDT)는 ‘내부 코드가 죽어도 보드는 다시 깨어난다’는 약속입니다.
  3. 두 가지가 함께 있을 때 우리는 ‘잊고 살 수 있는 노드 한 대’를 가지게 됩니다. 16대로 늘릴 때 사람의 손이 16배가 되지 않는 비결이 이 두 줄입니다.

🤖 AI에게 물어보기 · 같은 파일을 16번 다른 값으로 만드는 방법

  1. 16개 교실 각각의 secrets.py를 손으로 16번 고치는 일은 지루합니다. 우리는 곧 Unit 3에서 ‘하나의 템플릿에서 16개의 파일을 자동으로 만드는 방법’을 보게 됩니다.
  2. 시간이 남으면 챗 LLM에 ‘NODE_ID만 다른 16개의 파일을 한 번에 만들어 주는 셸 스크립트를 작성해 주세요’라고 부탁해 보세요. 어떤 코드가 돌아오는지 비교해 봅니다.
  3. 받은 스크립트가 안전한지 검증할 줄 아는 사람이, AI를 잘 쓰는 사람입니다.

단계 5 — 첫 부팅과 검증

우측 하단의 빨간 정지(⏹) 버튼을 누르면 보드가 한 번 더 재시작되며 main.py가 자동으로 실행됩니다.

실행 결과

이 다섯 줄이 5~15초 안에 차례로 나와야 합니다. 줄마다 어떤 의미가 담겨 있는지 한 번 짚어 봅니다.

  1. 부팅 — secrets.py의 NODE_ID가 정확히 읽혔다는 신호.
  2. I2C 스캔 — 0x44(SHT40)와 0x23(BH1750)이 모두 잡혔다는 신호. 둘 중 하나라도 빠지면 배선 단계로 돌아갑니다.
  3. WiFi 연결 시도 / 연결됨 — 학교 무선망에 정상적으로 붙었다는 신호. IP가 보이지 않으면 SSID·패스워드를 다시 확인합니다.
  4. 측정 — 실제 센서값이 30초마다 한 줄씩 새로 찍히는 신호.

측정값이 합리적인 범위인가

실제 환경에서 의미 있는 값이 나오는지를 빠르게 가늠해 봅니다. 첫 번째 측정값이 다음 범위 안에 들어와야 ‘정상’이라고 판단합니다.

항목정상 범위 (교실 실내)
온도 T15 ~ 35 °C
습도 RH20 ~ 80 %RH
조도 lux50 ~ 2,000 lux (형광등이 켜진 평일 낮 기준)

극단값이 보이면(예: T가 -45.0 또는 130.0) 센서 read 자체가 실패한 것이고, 보통 케이블이 흔들렸기 때문입니다.
