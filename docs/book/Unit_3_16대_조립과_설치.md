# Unit 3. 🎯 16대 조립과 설치


이번 시간에는 Unit 1에서 한 대로 검증한 노드를 **열여섯 배로 늘려** 16개 교실 각각에 설치해 보겠습니다. ‘한 대를 잘 만든 손은 16대도 잘 만든다’는 말은 절반만 맞습니다. 같은 작업을 16번 반복할 때, 사람은 반드시 어딘가에서 작은 실수를 하기 마련이고, 그 실수가 어느 노드에서 났는지 추적하기는 매우 어렵습니다. 그래서 우리는 ‘반복을 줄이는 자동화’를 함께 배웁니다.

이번 단원의 진짜 학습 포인트는 ‘**같음을 같게, 다름을 다르게 두는 설계 감각**’입니다. 16개의 피코에 들어가는 `main.py`와 `sensors.py`는 한 글자도 다르지 않습니다. 다만 `secrets.py`의 한 줄, 즉 `NODE_ID`만 노드마다 다릅니다. 우리는 이 ‘다른 한 줄’을 자동으로 16번 다르게 만들어 주는 짧은 스크립트를 손에 익히게 됩니다. 한 번 익혀 두면 32대로 늘릴 때도, 다른 학교에 키트를 보낼 때도 같은 도구가 그대로 일을 합니다.

또 하나, 이번 단원은 ‘**혼자가 아니라 팀으로 만드는 시스템**’이라는 새로운 차원을 다룹니다. Unit 1·2가 ‘선생님 혹은 교사 한 사람이 책상 앞에서 한 대 만드는’ 작업이었다면, Unit 3은 ‘조립팀 4~6명이 작업장에서 16대를 함께 만드는’ 작업입니다. 이 과정에서 학생들은 분업, 검수, 라벨링 같은 팀 작업의 기본기를 익힙니다. 페어 워크(pair work)와 표준 절차(standard operating procedure)라는 두 개념이 자연스럽게 손에 묻습니다.

## 이번 시간의 미션

작업이 끝났을 때 다음 다섯 가지가 모두 사실이어야 합니다.

1. NODE_ID ↔ 교실 ↔ MAC 주소 매핑표가 16행 채워져 있다.
2. 16개의 `secrets.py`가 NODE_ID만 다르게 자동 생성되어 있다.
3. 16개의 노드가 모두 작업장 WiFi에 한 번 이상 붙어 데이터를 보냈다.
4. 16개의 노드가 모두 ABS 박스 안에 안전하게 고정되어 있다.
5. 16개의 노드가 각각의 교실에 설치되어, 대시보드에 카드 16장이 동시에 표시된다.

> **🧠 컴퓨팅 사고력 · 16번을 16분의 1로 줄이기**
>
> 1. 16번을 그냥 반복하면 그것은 ‘노동’입니다.
> 2. 16번을 자동으로 돌리면 그것은 ‘시스템’입니다.
> 3. 16번을 한 번 짠 스크립트로 도는 동안 사람은 ‘검수와 라벨링’이라는 더 어려운 일에 집중할 수 있습니다.

> 📷 **그림 3-1** · 16세트 부품이 분류된 조립 작업장 전경
> *촬영 메모 — 큰 책상 위에 부품이 카테고리별로 정렬된 모습. 좌측부터 SHT40, Grove Light Sensor, Grove 케이블, USB 부품, ABS 박스가 한 줄씩.*

## 단계 1 — 부품 입고 점검

발주가 도착한 첫날 가장 먼저 해야 할 일은 ‘부품이 정말 다 왔는가, 그리고 정말 동작하는가’를 확인하는 일입니다.

### 1.1 수량 점검 (체크리스트)

BOM과 대조해 한 항목씩 체크합니다.

- [ ] SHT40 모듈 18개 (16 + 예비 2)
- [ ] Grove Light Sensor (P) v1.1 [101020173] 모듈 18개
- [ ] Grove 4핀 케이블 20cm 5pcs × 9팩 = 45개 (SHT40 + Light Sensor 둘 다 Grove-Grove)
- [ ] 마이크로 USB 케이블 19개

- [ ] ABS 박스 18개
- [ ] 케이블타이·라벨·절연테이프 1세트

### 1.2 표본 동작 점검

도착한 18개 SHT40·Grove Light Sensor를 모두 점검할 필요는 없지만, 무작위로 5개씩 골라 Unit 1의 파일럿 노드에 갈아 끼우며 SHT40은 셸의 I2C 스캔에 `0x44`가 잡히는지, Grove Light Sensor는 손으로 가렸을 때 `light` 값이 변하는지를 확인합니다. 한 개라도 인식이 안 되면 발주처에 그 라인 전체의 동작을 다시 문의해야 할 수도 있습니다.

> **Tip 표본의 크기**
>
> 1. 18개를 전부 검증하면 시간이 오래 걸립니다.
> 2. 무작위 5개의 표본이 모두 정상이라면, 나머지 13개가 모두 불량일 확률은 매우 낮습니다(통계적으로 표본 검사의 기본 원리).
> 3. 다만 ‘무작위’가 중요합니다. 상자 위쪽 5개만 보면 위쪽만 멀쩡할 가능성이 있습니다.

## 단계 2 — NODE_ID ↔ 교실 매핑표 만들기

16개의 피코는 ‘똑같은 16대’가 아닙니다. 어느 피코가 어느 교실에 가는지, 어느 학생이 책임지는지, MAC 주소가 무엇인지를 기록해 두지 않으면 한 달 뒤 ‘1학년 3반 노드가 안 들어와요’라는 신고를 받았을 때 어디서부터 봐야 할지 알 수 없습니다.

### 2.1 매핑표 형식

구글 시트로 만드는 것을 권장합니다. 16행을 미리 그려 두고 한 칸씩 채워 갑니다.

| NODE_ID | 교실 | 담당 학생 | MAC 주소 | 조립일 | 설치일 | 비고 |
|---|---|---|---|---|---|---|
| 1-1 | 1학년 1반 | 김ㅇㅇ | (미정) | (미정) | (미정) | |
| 1-2 | 1학년 2반 | 이ㅇㅇ | (미정) | (미정) | (미정) | |
| … | … | … | … | … | … | … |
| 3-8 | 3학년 8반 | 박ㅇㅇ | (미정) | (미정) | (미정) | |

> 📷 **그림 3-2** · 16행으로 채워진 NODE_ID 매핑표
> *촬영 메모 — 구글 시트 캡처. 16행의 NODE_ID, 교실, 담당 학생 열이 모두 채워진 모습.*

> **🤖 AI에게 물어보기 · 매핑표의 기본 구조**
>
> 1. 챗 LLM에 ‘우리 학교 16개 교실에 IoT 노드를 1대씩 설치합니다. 노드와 교실, 담당자를 추적하는 구글 시트 컬럼을 어떻게 설계하면 좋을지 추천해 주세요’라고 부탁해 봅니다.
> 2. ‘부착 위치(천장/벽/책상 위), 마지막 점검 일자, 알림 발송 여부’ 같은 컬럼이 추가 추천될 수 있습니다.
> 3. 첫 번째 표는 단순하게, 운영하면서 필요할 때마다 한 컬럼씩 늘려 갑니다.

## 단계 3 — MAC 주소 일괄 수집

학교 망이 MAC 등록제가 아니더라도, MAC을 기록해 두면 노드를 잃어버렸을 때 추적이 쉽습니다.

### 3.1 펌웨어에 MAC 출력 코드 한 줄 추가

`prototype/firmware/main.py`의 `connect_wifi()` 함수 안, `wlan.active(True)` 바로 다음 줄에 다음 두 줄을 추가합니다.

#### 코드 3-1

```python
import ubinascii
mac = ubinascii.hexlify(wlan.config('mac'), ':').decode()
log("MAC: {}".format(mac))
```

이 한 줄이 추가되면, 부팅 로그에 다음과 같은 줄이 한 번 더 찍힙니다.

```
[12420] MAC: 28:cd:c1:0e:5f:42
```

### 3.2 16대 MAC 일괄 수집 절차

본인 컴퓨터의 터미널에서 `mpremote`라는 도구를 한 번만 설치해 둡니다.

```bash
pip install mpremote
```

이후 각 피코를 USB로 연결하면서 다음 한 줄을 실행합니다.

#### 코드 3-2

```bash
mpremote exec "
import network, ubinascii
wlan = network.WLAN(network.STA_IF)
wlan.active(True)
print(ubinascii.hexlify(wlan.config('mac'), ':').decode())
"
```

##### 실행 결과

```
28:cd:c1:0e:5f:42
```

이 출력값을 매핑표의 해당 행에 옮겨 적습니다. 16대 모두 끝나면 매핑표의 MAC 열이 채워집니다.

### 3.3 라벨 부착

- ABS 박스 외부: 큰 라벨에 `1-1 1학년 1반`처럼 NODE_ID + 교실명
- Pico 본체: 작은 라벨에 NODE_ID만 (`1-1`)
- 박스 내부: MAC 라벨 (분실 대비)

> **Tip 라벨은 ‘떼지 못하게’**
>
> 1. 학생이 무심코 떼거나 청소하다 떨어지면 추적이 어려워집니다.
> 2. 라벨 위에 투명 절연 테이프를 한 번 더 덮어 두면 1년은 견딥니다.

## 단계 4 — 16개 `secrets.py` 자동 생성

이번 단원의 핵심 자동화입니다. 본인 컴퓨터의 터미널에서 다음 스크립트를 한 번만 돌립니다.

#### 코드 3-3

```bash
mkdir -p /tmp/climate365-configs

ROOMS=("1-1" "1-2" "1-3" "1-4" "1-5" "1-6" "1-7" "1-8" \
       "2-1" "2-2" "2-3" "2-4" "2-5" "2-6" "2-7" "2-8")
# 3학년 8반까지면 위 배열에 3학년 8개 더 추가

SRC=~/greatsong-project/climate-action-365/prototype/firmware/secrets.py

for room in "${ROOMS[@]}"; do
  sed "s/NODE_ID = \"PILOT\"/NODE_ID = \"$room\"/" "$SRC" \
    > /tmp/climate365-configs/secrets_$room.py
done

ls /tmp/climate365-configs/
```

##### 실행 결과

```
secrets_1-1.py  secrets_1-2.py  secrets_1-3.py  ...  secrets_2-8.py
```

16개의 파일이 한 번에 만들어졌습니다. 각 파일은 `NODE_ID` 한 줄만 다르고 나머지는 모두 같습니다.

> **🧠 컴퓨팅 사고력 · `sed` 한 줄이 16번의 손작업을 대신한다**
>
> 1. `sed`는 ‘찾아 바꾸기’를 명령어로 하는 도구입니다.
> 2. `for` 반복문은 16번 같은 작업을 다른 값으로 자동 실행합니다.
> 3. 이 두 도구를 합치면, 우리는 같은 패턴의 16개 파일을 1초 안에 만들 수 있습니다.

## 단계 5 — 일괄 배포 스크립트

이제 만들어진 16개의 `secrets.py`를 각 피코에 차례로 올리는 한 줄짜리 도구를 마련해 둡니다.

### 5.1 배포 스크립트

본인 컴퓨터의 홈 디렉터리에 `climate365-deploy.sh` 파일을 만듭니다.

#### 코드 3-4

```bash
#!/bin/bash
# 사용법: ./climate365-deploy.sh 1-1
set -e

if [ -z "$1" ]; then
  echo "사용법: $0 <NODE_ID>  (예: 1-1)"
  exit 1
fi

NODE_ID=$1
FW_DIR=~/greatsong-project/climate-action-365/prototype/firmware
CFG_DIR=/tmp/climate365-configs

echo "==> $NODE_ID 배포 시작"

mpremote rm :main.py || true
mpremote rm :sensors.py || true
mpremote rm :secrets.py || true
mpremote rm :buffer.jsonl || true

mpremote cp "$FW_DIR/sensors.py" :
mpremote cp "$FW_DIR/main.py" :
mpremote cp "$CFG_DIR/secrets_$NODE_ID.py" :secrets.py

echo "==> $NODE_ID 배포 완료. 재부팅..."
mpremote reset
echo "==> $NODE_ID OK"
```

실행 권한을 줍니다.

```bash
chmod +x ~/climate365-deploy.sh
```

### 5.2 16대 배포 흐름

각 피코를 차례로 USB에 꽂으면서 한 줄씩 실행합니다.

```bash
~/climate365-deploy.sh 1-1
# USB 분리, 다음 피코 연결
~/climate365-deploy.sh 1-2
# ...
~/climate365-deploy.sh 3-8
```

한 대당 약 5초가 걸리므로, 16대를 모두 배포하는 데 약 15~20분이 소요됩니다.

> **🤖 AI에게 물어보기 · 더 빨리 배포할 수는 없을까**
>
> 1. ‘USB 허브에 여러 피코를 동시에 꽂아 한꺼번에 배포할 수 있을까’라는 질문이 자연스럽게 떠오릅니다.
> 2. 실제로는 운영체제가 같은 시간에 여러 시리얼 포트(`/dev/cu.usbmodem…`)를 따로 인식하므로, 포트 이름을 인자로 받게 스크립트를 손보면 가능은 합니다.
> 3. 처음에는 한 대씩 가는 편이 안전합니다. 익숙해진 뒤 도전해 봅니다.

## 단계 6 — 조립 표준 절차

조립팀 학생 한 사람이 노드 한 대를 만드는 절차입니다. 두 명이 한 조가 되어 한 사람이 조립하고, 다른 한 사람이 같은 시간에 매핑표 갱신과 동작 검증을 맡는 ‘페어 워크’를 권장합니다.

### 6.1 1노드 표준 8단계

| Step | 작업 | 기준 |
|---|---|---|
| ① | Pico에 Grove Shield 끼우기 | 정렬에 무리하지 않음 |
| ② | SHT40 Grove 케이블로 I2C 슬롯에 연결 | 한 방향만 들어감 |
| ③ | Grove Light Sensor를 A0 슬롯에 Grove 케이블로 연결 | Shield 전원 스위치 3.3V 확인 |
| ④ | 마이크로 USB 케이블 연결 + 전원 인가 | Pico LED 점등 |
| ⑤ | 작업장 WiFi에서 동작 검증 | 대시보드에 NODE_ID 카드 표시 |
| ⑥ | ABS 박스에 모듈 고정 | 양면테이프 + 케이블타이 |
| ⑦ | 라벨링 (NODE_ID + 교실명) | 박스 외부·내부 두 곳 |
| ⑧ | 매핑표 ‘조립 완료’ 체크 | 조립일 기록 |

> 📷 **그림 3-3** · 한 노드의 표준 8단계 조립 과정
> *촬영 메모 — 8개의 작은 사진을 격자(2×4)로 배치. 각 사진에 ① ② ③ … 번호 표시.*

### 6.2 통기 구멍 가공

ABS 박스를 그대로 닫아 두면, 박스 내부 온도가 교실 온도보다 2~3°C 높게 측정될 수 있습니다. 미세한 ‘통기’가 필요합니다.

- Grove Light Sensor(조도 센서) 쪽 박스 측면에 직경 5~10mm 작은 구멍 1개 (빛이 충분히 들어오게)
- 박스 측면·상면에 1~2mm 폭의 슬릿 몇 줄 (공기 순환용)

3D 프린팅이 아닌 시판 ABS 박스는 줄톱이나 드릴로 손가공이 필요합니다. 안전을 위해 교사 감독 하에 진행합니다.

> **🔬 가설을 세워 봅시다 · 박스가 측정에 영향을 줄까**
>
> 1. ‘박스 안과 박스 밖의 온도는 같을까’를 가설로 둡니다.
> 2. 박스 안에 노드를 두고 한 시간, 박스 밖에 두고 한 시간 측정한 뒤 두 평균을 비교합니다.
> 3. 차이가 있다면 그것이 바로 ‘통기 구멍이 필요한 이유’의 데이터 증거입니다.

## 단계 7 — 교실 설치

조립이 끝난 노드를 각 교실에 가져가 콘센트에 꽂는 일은 매우 짧은 작업이지만, ‘어디에 두느냐’가 측정의 품질을 좌우합니다.

### 7.1 설치 위치 원칙

| 원칙 | 이유 |
|---|---|
| 호흡 높이 1.0~1.5m | 학생이 실제 호흡하는 공기를 측정 |
| 직사광선 X | 조도 센서 왜곡, 온도 인공 상승 방지 |
| 콘센트 가까이 (1m 이내) | USB 어댑터 줄 길이 한계 |
| 에어컨·히터·창문 정통 X | 국부 온도 영향 |
| 학생 손이 닿지 않는 곳 | 안전·고장 방지 (캐비닛 위·게시판 옆 벽) |
| 천장 X | 호흡 높이가 아님 |

### 7.2 설치 5분 절차

1. 교실 진입, 위치 선정 (위 원칙 따라)
2. 양면테이프 또는 케이블타이로 박스 고정
3. USB 어댑터 콘센트에 꽂기
4. 전원 인가 후 30초~1분 대기
5. 스마트폰으로 대시보드 열기 → 해당 NODE_ID 카드의 ‘마지막 수신’이 1분 이내인지 확인
6. 매핑표에 설치 완료 시각 기록
7. 교실 담임에게 ‘이 박스는 환경 측정용이며 분리하지 말 것’ 한 줄 안내

> 📷 **그림 3-4** · 교실 벽에 부착된 완성 노드
> *촬영 메모 — 교실 한쪽 벽의 1.2m 높이에 ABS 박스가 부착된 모습. 박스 외부 라벨 ‘1-1 1학년 1반’이 잘 보이게.*

## 단계 8 — 16대 동시 검증

모든 노드가 설치된 뒤, 학생 운영팀이 전체를 한 번에 점검하는 ‘전체 검증’을 실행합니다.

### 8.1 대시보드 ‘전체 교실’ 탭

본인 컴퓨터 또는 스마트폰 브라우저에서 다음을 엽니다.

```
http://192.168.0.10:8501
```

‘전체 교실’ 탭에 16장의 카드가 4×4 격자(또는 비슷한 배치)로 보이고, 모든 카드에 🚨 표시가 없으면 성공입니다.

### 8.2 서버 측 점검

라즈베리 파이에 SSH 접속해 다음을 실행합니다.

#### 코드 3-5

```bash
sqlite3 /home/pi/climate-action-365/prototype/server/data.db <<EOF
.mode column
.headers on
SELECT node_id, COUNT(*) as count, MAX(received_at) as last_seen
FROM readings
WHERE received_at >= datetime('now','-10 minutes')
GROUP BY node_id
ORDER BY node_id;
EOF
```

##### 실행 결과

```
node_id  count  last_seen
1-1      20     2026-05-21 14:32:11
1-2      19     2026-05-21 14:32:08
1-3      20     2026-05-21 14:32:15
...
3-8      18     2026-05-21 14:31:57
```

16행이 모두 보이고 `count`가 10건 이상씩 쌓여 있으면 완벽합니다.

> **📊 데이터 잠깐 들여다보기 · 16행이 한 줄 짧을 때**
>
> 1. 만약 15행만 보인다면, 한 노드가 어딘가에서 막혔다는 뜻입니다.
> 2. 매핑표에서 누락된 NODE_ID를 찾아 그 교실로 갑니다.
> 3. ‘대시보드에 안 보이는 노드’가 늘 ‘죽은 노드’는 아닙니다. 가끔 WiFi에 한 번도 못 붙은 ‘덜 깨어난 노드’입니다.

### 8.3 헬스체크 스크립트 (한 줄로 16노드 상태 보기)

같은 SQL을 운영팀이 매일 손으로 두드릴 수는 없습니다. 본인 컴퓨터의 터미널에 다음 한 줄짜리 스크립트를 만들어 두면, 언제든 `./healthcheck.sh`만 치면 16노드 상태가 표로 정리됩니다.

#### 코드 3-6

```bash
#!/bin/bash
# ~/climate365-healthcheck.sh
# 16노드의 ‘최근 5분 수신 여부 + 평균값’ 표 출력
SERVER=http://192.168.0.10:8000

curl -s "$SERVER/nodes" | python3 - <<'PY'
import json, sys
from datetime import datetime, timezone, timedelta

nodes = json.load(sys.stdin)
now = datetime.now(timezone.utc)
print(f"{'NODE':<6} {'상태':<4} {'온도':>6} {'습도':>6} {'조도':>7}  마지막 수신")
print("-" * 60)
for n in sorted(nodes, key=lambda x: x["node_id"]):
    last = n.get("last_seen") or ""
    try:
        age = (now - datetime.fromisoformat(last)).total_seconds() / 60
        status = "🟢" if age < 5 else "🚨"
    except Exception:
        status = "❓"
    L = n.get("latest") or {}
    t  = f"{L.get('temperature') or 0:.1f}"
    rh = f"{L.get('humidity') or 0:.1f}"
    lx = f"{L.get('light') or 0:.1f}"
    print(f"{n['node_id']:<6} {status:<4} {t:>6} {rh:>6} {lx:>7}  {last[:19]}")
PY
```

##### 실행 결과

```
NODE   상태   온도    습도     조도   마지막 수신
------------------------------------------------------------
1-1    🟢    24.3   45.2     287   2026-05-21 14:32:11
1-2    🟢    23.7   47.1     312   2026-05-21 14:32:08
1-3    🚨     0.0    0.0       0
...
```

🚨가 한 행이라도 보이면 그 NODE_ID를 매핑표에서 찾아 해당 교실로 갑니다.

### 8.4 16노드 일괄 재배포 헬퍼 (Phase 2 확장 시 활용)

펌웨어를 한 번 갈아엎어야 하는 날(예: 새 학기 WiFi 패스워드 변경, Phase 2 SCD41 드라이버 추가)이 옵니다. 그때 한 줄로 16대를 차례로 재배포하는 보조 스크립트입니다.

#### 코드 3-7

```bash
#!/bin/bash
# ~/climate365-deploy-all.sh
# 16대를 한 명령으로 차례 배포. 각 Pico를 USB로 갈아 꽂으면서 Enter 입력.
ROOMS=(1-1 1-2 1-3 1-4 1-5 1-6 1-7 1-8 \
       2-1 2-2 2-3 2-4 2-5 2-6 2-7 2-8)
for room in "${ROOMS[@]}"; do
  read -p "==> [$room] 노드를 USB에 꽂은 뒤 Enter (스킵: s + Enter): " ans
  if [ "$ans" = "s" ]; then
    echo "  ↳ $room 스킵"; continue
  fi
  ~/climate365-deploy.sh "$room"
done
echo "전체 배포 완료."
```

이 스크립트의 가장 큰 효과는 ‘**실수를 못 하게 만드는 것**’입니다. 16대를 손으로 일일이 명령어 치다 보면 같은 NODE_ID로 두 번 배포하거나, 한 대를 빠뜨리거나 합니다. 이 한 줄의 `read -p`가 그 실수를 막아 줍니다.

> **🧠 컴퓨팅 사고력 · ‘짧은 자동화’가 ‘긴 매뉴얼’을 이긴다**
>
> 1. 똑같은 명령어를 16번 치는 매뉴얼을 작성하는 것보다, 한 줄짜리 스크립트로 자동화하는 것이 항상 더 짧고 더 정확합니다.
> 2. 매뉴얼은 사람이 한 번씩 어긴다(또는 못 본다)는 점에서 위험합니다. 스크립트는 어기지 못합니다.
> 3. 이 단원의 모든 코드는 ‘사람이 안 잊어버리도록 시스템에게 기억을 맡긴다’는 같은 원리에 서 있습니다.

## 🌟 리터러시 모먼트

> **🧠 컴퓨팅 사고력 · 표준 절차(SOP)의 힘**
>
> 1. 8단계 표준 절차를 ‘아는 사람’이 다음 작업자에게 가르치는 데 걸리는 시간이 매우 짧아집니다.
> 2. 표준 절차의 가장 큰 장점은 ‘속도’가 아니라 ‘실수가 어디에서 났는지 찾기 쉬움’입니다.
> 3. 학교 동아리, 회사, 병원, 공장 — 모든 조직은 SOP로 실수를 관리합니다.

> **🔬 가설을 세워 봅시다 · 같은 교실 두 노드의 값은 얼마나 같을까**
>
> 1. 두 노드를 같은 교실에 두면 두 측정값이 ‘완전히 같을까’를 가설로 둡니다.
> 2. 실제로는 ±0.3°C, ±2 %RH, ±5% 정도의 차이가 자연스럽습니다.
> 3. 이 ‘자연스러운 차이’를 알면, 측정값 하나로 단정 짓지 않고 ‘유의미한 변화인지’를 판단할 수 있습니다.

> **📊 데이터 잠깐 들여다보기 · 16개 NODE의 같음과 다름**
>
> 1. 16개 교실의 측정값은 ‘같은 학교’라는 점에서 같고, ‘다른 위치’라는 점에서 다릅니다.
