## ③ 안별 상세

### A안 — 빠른 시작 (절감형)

**철학:** "완벽보다 시작이 먼저." 한 학기 안에 16개 교실에서 데이터가 흐르게 한다.

**아키텍처:**
```
[교실 Pico] ──HTTP POST(JSON)──> [라즈베리파이4 FastAPI]
                                   ↓
                                 [SQLite]
                                   ↓
                                 [Streamlit]
```

**장점:**
- 학생이 모든 코드(펌웨어·서버·대시보드)를 손댈 수 있음 — 가장 높은 교육적 노출
- HTTP는 학교 방화벽 친화적, MQTT 포트 차단 리스크 회피
- SQLite는 설치·백업·이해가 가장 단순
- 예산 압박이 클 때 학교회계만으로 즉시 시작 가능

**단점:**
- 동시접속 한계: Streamlit Tornado 기반, 전교생 동시 접속에 약함
- CO₂ 측정 미흡 (MH-Z19B는 정확도 SCD41 대비 낮음, 또는 아예 미측정)
- 미세먼지 PMS7003 단독은 저오염 교실 정확도 한계 (기준점 부재)
- 알림 빈약 (Streamlit은 24/7 알림에 부적합)
- 확장성·재사용성 낮음

**적합한 상황:**
- 예산 ₩1.5M 이하로 제약된 경우
- "올해 안에 일단 가동"이 최우선 목표
- 본격 운영 전 1차 시범 단계로 활용 후 B/C로 업그레이드 예정

### B안 — 표준 (권장 ⭐)

**철학:** 트랙 4개 리서치가 공통으로 가리키는 균형점. **현재 시점의 최적합.**

**아키텍처:**
```
[교실 Pico ×16] ──MQTT──> [Mosquitto] ──> [InfluxDB 2.x]
                                            ↓        ↓
                                         [Grafana] [Streamlit]
                                          (운영팀)  (분석팀)
```

**센서 구성:**
- 표준 16노드: **PMS7003 + SHT40 + BH1750 + SCD41**
- 추가 2개: **SPS30 기준점 노드 2대** (예: 1층 1대, 4층 1대) → 분석팀이 PMS7003과 비교해 캘리브레이션 계수 산출 → **학생이 직접 정밀도 검증 경험**

**대시보드 하이브리드:**
- **Grafana** (운영팀·전교생 공개): 실시간 16교실 그리드, 임계값 색상, 자동 알림
- **Streamlit** (분석팀·교사): Pandas 분석, 가설 검증, 월간 리포트 자동 생성

**장점:**
- 트랙 A 권장(미세먼지 혼합), 트랙 B 권장(Mosquitto + 라즈베리파이), 트랙 C 권장(하이브리드 대시보드)가 모두 충족
- 학생 팀별 역할이 자연스럽게 분리 (조립=Grove 배선, 분석=Streamlit/Pandas, 운영=Grafana)
- 확장성 양호 (다른 학교에 키트 이식 쉬움)
- AirGradient·WeatherDuino 케이스 리믹스로 3D 프린팅 진입장벽 낮음

**단점:**
- 학교망 WiFi 인증·MQTT 포트 정책 사전 협의 필수 (안 풀리면 시작 지연)
- 라즈베리파이4·InfluxDB·Grafana·Mosquitto 4가지 컴포넌트를 누군가는 알아야 함 (사용자 또는 정보교사 운영팀)
- 초기 구축 10~12주 (한 학기 절반)

**적합한 상황:**
- 예산 ₩2.5M 정도 확보 가능
- 학교 네트워크 관리자와 협의 가능
- 본격 운영을 1년 이상 지속 계획

### C안 — 정밀·연구형

**철학:** 측정 데이터 자체로도 학술·정책 가치를 만든다. 당곡고를 국내 선도 사례로.

**추가 요소(B안 대비):**
1. **모든 노드 SPS30** — 학교 IAQ 학술 수준 정밀도 (±10% MCERTS)
2. **실외 1대** — Montana 사례 모방 (실내/실외 비교가 환기 시점 의사결정 핵심)
3. **TVOC SGP40 + 조도 VEML7700** — PM·CO₂ 외 항목까지 학교 수준 자체 임계값 연구
4. **Superset 2년차 SQL 트랙** — 분석팀 졸업생이 후배에게 SQL 가르치는 구조
5. **클라우드 미러** (HiveMQ Cloud 무료 티어 또는 자체 VPS) — 데이터 손실 방어 + 외부 공개

**장점:**
- keep.go.kr 우수환경동아리·탄소중립 중점학교 자료집 출품 시 **국내 사례 부재 영역(16교실급 학생 운영 실시간 IoT)**의 선도 사례 가능성
- 데이터 품질이 논문 인용·정책 자료 활용 수준
- 학년·기수가 쌓이면서 운영팀·분석팀 모두 깊은 학습 곡선

**단점:**
- 예산 60~70% 증가 (₩3.5M~4M)
- SPS30 ×16은 발주·납기 부담 (해외 구매 가능성)
- 초기 14~16주 + 안정화까지 1년 가까이 소요
- 학생 학습 곡선이 가파름 → 초기 신입생 진입장벽

**적합한 상황:**
- 환경부 keep.go.kr 공모 또는 교육청 미래교육 공모로 외부 예산 확보 가능
- 다년 운영 계획 (3~5년)
- 동아리 학생 핵심 멤버가 3학년 졸업 후에도 후배에게 인계 가능한 체계 구축 의지

## ④ 결정 가이드

다음 질문에 답해보면 어느 안인지 빠르게 좁힐 수 있습니다.

| 질문 | A | B | C |
|---|---|---|---|
| 예산 ₩1.5M 이하 확정인가? | ✅ | | |
| 1년차에 안정 운영, 2~3년차에 확장 계획? | | ✅ | |
| 외부 공모·논문·자료집 출품을 산출물 목표로 둘 것인가? | | | ✅ |
| 학교 네트워크 관리자 협의가 어려울 가능성? | ✅ | | |
| 학생들이 모든 코드(서버·대시보드)를 손댈 수 있길 원하는가? | ✅ | | |
| 전교생·학부모 공개 대시보드까지 가야 하는가? | | ✅ | ✅ |
| 16교실 외 실외·체육관·다른 학교까지 확장 가능성? | | ✅ | ✅ |

**추천 — B안 (표준)**: 트랙 4개 리서치가 모두 가리키는 균형점이며, A → B 업그레이드는 비용이 들지만 B → C 업그레이드는 비교적 쉽습니다 (센서 추가 + 대시보드 추가만). A에서 출발하면 통신·서버·대시보드 전체를 갈아엎어야 합니다.

> 단, 예산이 ₩1.5M 이하로 확정되어 있다면 **A로 1년 시범 → 다음 해 B로 본격 운영**이 현실적 경로일 수 있습니다.

## ⑤ 선결 액션 아이템 (안 무관 공통)

### 사용자(석리송) 확인 필요

- [ ] **학교 네트워크 관리자 문의** — 다음 3개를 한번에:
  1. 학교 WiFi 인증 방식 (WPA2-PSK / WPA2-Enterprise)
  2. IoT 전용 SSID(WPA2-PSK) 발급 가능 여부
  3. Outbound 1883/8883(MQTT) 및 443(WebSocket) 포트 정책
- [ ] **3D 프린터 가용성** — 학교 메이커스페이스 보유 여부 (없으면 케이스 외주·시판 검토)
- [ ] **예산 확보 경로** — 학교회계 단독 / 환경부 keep.go.kr 공모 / 교육청 미래교육 / 학부모회
- [ ] **데이터 공개 정책** — 교내 IP만 / 전교생 ID 인증 / 학부모 공개 / 외부 완전 공개?
- [ ] **TVOC 측정 필요성** — 분석팀 R&D 트랙으로 의미 있는가? (학교 기준 없음 = 학생이 임계값 설계)
- [ ] **운영 시작 목표 시점** — 2026년 2학기 시작? 2027년 1학기?

### 발주 전 재확인 필요

- [ ] 디바이스마트·아이씨뱅큐 실시간 가격 (트랙 A·D 견적은 추정치)
- [ ] Pico 2 WH 한국 정식 유통 여부 (트랙 D에 가격 미공개로 표시됨)
- [ ] SPS30 한국 재고·납기 (해외 직구 시 통관·환율 영향)
