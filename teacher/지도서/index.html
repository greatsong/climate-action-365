교사용 통합 지도서

이 문서는 기후행동365 16교실 환경 모니터링 시스템을 학생과 함께 운영하는 **정보교사(또는 환경교사)**를 위한 지도서입니다. 학생용 본문(Unit 1~4)은 학생이 직접 따라 읽고 손에 익힐 수 있게 만들어졌다면, 이 지도서는 교사가 ‘무엇을 어떤 순서로, 어떻게 평가하면서’ 끌고 갈지에 대한 안내입니다.

이 문서는 한 학기를 16주로 잡았을 때의 표준 일정을 따릅니다. 다만 학교 사정에 맞게 압축·확장이 가능합니다. 또한 정보·과학·사회·환경 네 과목의 교육과정 요소를 표 한 장에 매핑해 두었으므로, 교과 융합 수업이나 동아리 활동 어느 형태로도 활용할 수 있습니다.

이 시스템은 1~2학기 안에 끝나는 단발 프로젝트가 아닙니다. 학년 단위로 진화하며, 졸업하는 학생이 다음 학년에 인계하는 ‘세대 계승형 프로젝트’로 설계되어 있습니다. 첫 학년의 가장 큰 산출물은 ‘동작하는 시스템’이지만, 그보다 중요한 산출물은 ‘다음 학생이 이어받을 수 있는 형태로 정리된 매뉴얼·데이터·관계 기록’입니다.

2. 단원별 지도안

Unit 1 지도안 — 파일럿 한 대 세팅

학습 목표 (학생 시점)

  • 마이크로파이썬 펌웨어를 보드에 직접 설치할 수 있다.
  • Thonny에서 보드와의 연결을 진단할 수 있다.
  • I2C 스캔 결과를 보고 배선 문제와 펌웨어 문제를 구분할 수 있다.

수업 시간 배분 (90분 × 2회)

회차시간활동
1회차0~15분단원 도입 — 16대 작업 전 ‘1대 검증’의 의미
15~50분펌웨어 플래시 + Thonny 설치 (학생 손)
50~75분센서 배선 + I2C 스캔
75~90분트러블슈팅 시연 (교사 의도적 실수)
2회차0~15분secrets.py 작성
15~45분첫 부팅 + 셸 로그 해석
45~75분서버 수신 확인 (서버는 노트북으로 임시 가동)
75~90분통합 검증 체크리스트 통과

교사용 코칭 포인트

  1. ‘BOOTSEL 모드’ 시연을 두 번: 한 번은 천천히, 한 번은 정상 속도. 학생이 실수했을 때 부담을 줄여 줍니다.
  2. I2C 스캔에 0x44만 보이게 의도적 실수: BH1750의 점퍼 한 줄을 일부러 빼고 보여 줍니다. ‘이 한 줄로 모듈이 사라진다’는 체감이 가장 강한 학습입니다.
  3. WiFi 패스워드는 칠판에 적지 않습니다: 학생이 각자 보안 채널로 받아 입력하게 합니다. 보안 교육의 작은 시작입니다.

예상 어려움 3가지와 대응

어려움대응
Thonny가 포트를 못 찾는다케이블 ‘전원 전용’ 의심 → 다른 케이블로 교체
0x23이 안 보인다변환 케이블의 SDA·SCL 교차 확인 (90%가 여기)
측정값이 -45°C 등 극단값케이블 접촉 불량 → 한 번 뺐다 다시 끼우기

평가 루브릭 (각 5점)

  • 펌웨어 플래시 성공 (5점)
  • I2C 스캔에 0x44와 0x23 모두 확인 (5점)
  • 서버 /nodes에 PILOT 표시 확인 (5점)
  • 트러블슈팅 한 가지 자력 해결 (5점)
  • 단원 후 ‘셸 다섯 줄의 의미’를 친구에게 1분 안에 설명 (5점)

Unit 2 지도안 — 라즈베리 파이 5 서버

학습 목표

  • 라즈베리 파이 OS의 헤드리스 설치 흐름을 이해한다.
  • Pi 5의 전원·쿨링·EEPROM 차이를 손으로 익힌다.
  • systemd 단위 파일을 읽고 의미를 설명할 수 있다.
  • cron으로 자동화 작업을 등록할 수 있다.

수업 시간 배분 (90분 × 2회)

회차시간활동
1회차0~20분‘서버라는 컴퓨터의 시점’ 도입 강의 + 왜 Pi 5 16GB인가
20~50분OS 굽기 + 사전 설정 (Pi Imager, 디바이스: Pi 5 선택)
50~70분첫 부팅 + 5A 전원 메시지 확인 + EEPROM 업데이트
70~90분SSH 접속 + 고정 IP 설정
2회차0~20분scp로 프로젝트 복사, 가상환경
20~45분systemd 서비스 등록 (서버)
45~65분대시보드 서비스 등록
65~80분재부팅 자동 시작 검증 + cron 백업
80~90분쿨링 모니터링(vcgencmd measure_temp) + 16GB 의미 회고

교사용 코칭 포인트

  1. 고정 IP의 중요성을 ‘만약 IP가 바뀐다면’ 시나리오로: 16대가 한꺼번에 못 붙는 상상을 학생에게 시켜 줍니다.
  2. 5V/5A 전원의 의미: 부팅 직후 ‘5A 전원이 아닙니다’ 메시지를 한 번 일부러 보여 줍니다. 5V/3A 어댑터를 같이 가지고 와서 ‘잘못 꽂으면 USB 키보드가 안 먹는다’를 시연하면 강하게 박힙니다.
  3. EEPROM은 한 번만: 출고 후 첫 1회만 필요하고, 그 다음부터는 안 해도 됩니다. ‘바이오스 업데이트와 비슷하다’로 설명합니다.
  4. systemd 단위 파일의 줄을 한 줄씩 풀이: 학생이 ‘리눅스라는 운영체제도 사람이 정한 약속이다’를 체감하게 합니다.
  5. 백업의 ‘동기’를 강조: ‘카드가 망가질 수 있다’는 사실을 사진(까맣게 탄 microSD 등)으로 보여 주면 효과가 큽니다.
  6. 16GB의 의미 회고: 마지막 10분에 free -h로 ‘14GB가 비어 있다’를 보여 주고, 1년 뒤 분석팀이 이걸 쓰게 될 거라는 한 줄 예고를 남깁니다.

예상 어려움

어려움대응
nmcli로 IP 바꾸다 SSH 끊김키보드·모니터를 한 번 더 연결, IP 재확인 후 재접속
‘5A 전원 아님’ 경고 계속 보임정품 27W 어댑터인지 확인. 일반 USB-C 충전기는 보통 5V/3A까지만.
EEPROM 업데이트 실패인터넷 연결 확인 후 sudo apt update && sudo apt install rpi-eeprom로 재시도
Pi 5 발열vcgencmd measure_temp 80°C 이상이면 케이스 통풍·팬 동작 점검
서비스가 failedjournalctl -u climate365 -e의 마지막 30줄을 다 같이 읽기
cron이 안 도는 것 같음시각 동기화(timedatectl) 확인 — 학교 망에서 NTP가 막혔을 수도

평가 루브릭

  • 헤드리스 OS 설치 성공 (5점)
  • EEPROM 업데이트 1회 실행 (5점)
  • 고정 IP 적용 (5점)
  • systemd 두 서비스 모두 active (running) (5점)
  • 재부팅 후 자동 시작 검증 + 쿨링 60°C 이하 확인 (5점)

Unit 3 지도안 — 16대 조립과 설치

학습 목표

  • 16개의 NODE_ID·교실·MAC 매핑을 체계적으로 관리할 수 있다.
  • 셸 스크립트로 같은 파일을 16번 ‘다르게’ 자동 생성할 수 있다.
  • 팀 작업의 표준 절차(SOP)를 설계·운영할 수 있다.

수업 시간 배분 (180분 워크숍 1회 + 설치 60분)

시간활동
0~20분매핑표 함께 만들기 (16행 디자인)
20~40분펌웨어에 MAC 출력 추가 + 16대 MAC 수집
40~60분secrets.py 자동 생성 시연
60~150분페어 8조 동시 조립 (4명×2개 노드씩 → 8노드 / 또는 1인 1노드)
150~180분라벨링, 통기 구멍 가공, 작업장 검증
별도 60분교실 설치 (운영팀 4명, 교사 동행)

교사용 코칭 포인트

  1. ‘페어 워크’의 역할 분담: 처음 30분만 ‘둘 다 조립’으로 가다가, 이후엔 한 사람은 조립·다른 한 사람은 매핑표 갱신이 자연스럽게 자리 잡습니다.
  2. 조립 워크숍 중 5분 휴식 의무화: 작은 부품을 만지는 일은 집중력을 빨리 소진시킵니다. 25분 작업 + 5분 휴식 사이클을 권장합니다.
  3. 통기 구멍 가공은 교사가 직접: 줄톱·드릴 작업은 안전을 위해 교사가 맡습니다(또는 학교 메이커 교사 협조).

예상 어려움

어려움대응
sed 스크립트가 안 돈다매크OS와 리눅스의 sed 옵션 차이 — sed -i '' vs sed -i
학생이 색상 매핑을 매번 다르게 푼다작업장 벽에 큰 ‘색상 대조표’ 부착
조립 워크숍이 시간 초과8명 페어 → 6명 페어로 줄이고 2회로 나눔

평가 루브릭 (팀 평가)

  • 매핑표 16행 완성 (5점)
  • 자동 생성 스크립트 1회 성공 실행 (5점)
  • 16노드 모두 작업장 WiFi에 한 번 이상 붙음 (5점)
  • 16노드 모두 교실에 안전하게 설치 (5점)
  • 페어 워크 협업 관찰 평가 (5점)

Unit 4 지도안 — 운영과 장애 대응

학습 목표

  • 일일/주간/월간 점검의 시간 단위 차이를 설명할 수 있다.
  • SQL 한 줄로 결측률을 조회하고 해석할 수 있다.
  • 장애 발생 시 표준 30분 복구 절차를 수행할 수 있다.

수업 시간 배분 (45분 × 다회 + 월간 리포트 1회)

회차시간활동
1회45분다섯 줄 점검 양식 만들기 + 일주일 시범 운영
2회45분장애 시나리오 롤플레이 (교사가 USB를 뺀다)
3회45분주간 점검 SQL 한 줄 작성·해석
4회45분분석팀 Pandas 기초
월간90분첫 월간 리포트 작성 + 발표 리허설

교사용 코칭 포인트

  1. 장애 롤플레이는 의도적으로: 교사가 노드 하나의 USB를 빼면, 운영팀이 ‘5분→10분→15분’ 복구 절차를 손에 익힙니다. 실제 사고 전에 ‘훈련된 대응’을 만들어 둡니다.
  2. 월간 리포트는 ‘완성도’보다 ‘리듬’: 첫 리포트는 어설퍼도 됩니다. 매달 같은 형식으로 5분 발표가 굴러가는 것이 더 중요합니다.
  3. 분석팀의 데이터 접근 권한: 학생에게 SSH 비밀번호를 직접 주기보다, 백업본 .db 파일을 USB로 받아 본인 컴퓨터에서 분석하게 합니다.

6. 자주 묻는 질문 (FAQ)

Q1. 학생이 코드를 직접 짜야 하나요?

A. 거의 짜지 않습니다. 펌웨어·서버·대시보드는 모두 미리 만들어져 있으며, 학생은 ‘이미 만들어진 코드를 읽고 의미를 이해하며, 설정과 운영을 하는’ 역할을 맡습니다. 다만 분석팀이 Pandas/SQL로 데이터를 만지는 일은 권장합니다. 챗 LLM과 함께 코드를 만드는 ‘바이브 코딩’ 모드를 자연스럽게 익히게 됩니다.

Q2. 학교 망 보안 정책이 까다로워서 IoT 접속이 안 되면 어떻게 하나요?

A. 별도 IoT 전용 SSID(WPA2-PSK) 발급이 가장 깔끔한 해법입니다. 그것이 어려우면 학교 내 공유기 한 대를 추가 설치해 ‘동아리 망’을 따로 만드는 방법도 있습니다. 다만 신호 도달 범위가 16교실을 다 덮어야 하므로, 처음부터 학교 망에 얹는 편이 안정적입니다.

Q3. 학생이 정전 사고 같은 일로 시스템을 손상시키면 어떻게 하나요?

A. 본 시스템은 ‘정전 복구 자동화’를 전제로 설계되어 있습니다. systemd와 cron이 거의 모든 일을 자동 복구합니다. 학생이 만질 수 있는 가장 위험한 부분은 ‘USB 어댑터 콘센트’이며, 이는 시스템에 손상을 주지 않습니다(자동 재부팅). 다만 microSD를 빼는 일은 위험하므로 평소에 라즈베리 파이 케이스를 봉인해 둡니다.

Q4. 운영팀 학생이 매일 점검을 안 하면 어떻게 하나요?

A. ‘매일 5분 점검’이 의무가 아니라 ‘재미있는 습관’이 되도록 디자인합니다. 슬랙·노션의 자동 알림, 한 줄 일지의 ‘긴 줄이 좋다’ 같은 게이미피케이션, 분석팀의 ‘이번 주의 발견’ 코너 등이 도움이 됩니다. 한 달간 점검이 끊긴 노드는 ‘점검 보고서’의 첫 데이터로 활용해 ‘무관심도 데이터다’를 학생에게 가르치는 기회로 삼습니다.

Q5. Phase 2(CO2) 추가는 언제, 어떻게 결정하나요?

A. Phase 1(온습도+조도) 운영이 한 학기 이상 안정적으로 굴러가고, 분석팀이 ‘CO2 데이터가 있다면 더 많은 발견이 가능했을 것이다’라는 결론에 자력으로 도달했을 때가 적기입니다. 예산은 환경부·교육청 공모로 별도 확보를 권장합니다. 펌웨어·서버·대시보드는 Phase 2 추가를 미리 염두에 두고 설계되어 있으므로(예약 컬럼·확장 포인트), 발주만 결정되면 1~2주 내 추가가 가능합니다.

7. 졸업·인계 패키지 권장 구성

학년말에 졸업하는 학생이 다음 학년에 넘기는 ‘인계 패키지’ 권장 구성입니다.

  1. 매핑표 1년치 (구글 시트 사본)
  2. 일일 점검 한 줄 일지 1년치
  3. 월간 리포트 6~10편
  4. 데이터 백업본 (data-final-YYYY.db)
  5. 자주 발생한 장애 5건과 해결 노트
  6. 다음 학년 1학기 계획 초안
